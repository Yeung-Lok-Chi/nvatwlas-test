Data and attribution

The corpus contains 500 sentence pairs supplied in NVAtlas-AI-Agent.csv. The public NV Atlas identifies its material as the OpenSubtitles v2024 corpus and describes its processing with POS tagging and a local AI model followed by human inspection. This site uses the supplied subset and does not claim ownership of the source dialogue.

Reconciliation and checking

Every one of the 500 IDs was found in the public NV Atlas search payload. Exact matching produced 343 identical pairs. After Unicode NFKC and whitespace normalization, 481 pairs matched; 19 retained visible source variants. The variants are listed in data/audit.json.

Loading reconciliation report…

The required 50-entry human check is prepared, not falsely completed. A fixed random sample of 50 IDs was selected with seed 20261105 and is visible in the 50-row audit sample filter. The records are reconciled programmatically; the student still needs to read and approve them before changing human_checked to yes.

AI Use Declaration

Tools and model

OpenAI Codex desktop agent, using the model identifier deepseek/deepseek-v4.1-flash-1017 as shown in the writing session. PDF extraction and the site’s static tooling were used locally. The public NV Atlas page was consulted for source information and record reconciliation.

What AI did

  • Read and summarize the project brief.
  • Audit the supplied CSV for shape, duplicates, IDs, and term counts.
  • Extract the public NV Atlas records for verification, without generating replacement sentences.
  • Draft the codebook structure, normalize the data schema, and build the HTML/CSS/JavaScript explorer.
  • Draft English and Traditional Chinese explanatory prose.
  • Test the site’s calculations, links, URL state, and responsive layout.

What I must do myself

  • Read and approve the 50-record verification sample against the source.
  • Rewrite the codebook definitions in my own words before submission.
  • Verify the analysis and be ready to explain each category orally.
  • Confirm that the public display of short subtitle excerpts is acceptable under the applicable course and source terms.

Verified and not verified

Verified: 500 unique IDs, 195 unique lemmas, 282 Chinese renderings, all IDs present in the public record set, and 481 normalized matches. Not verified: whether each translation is a good translation; whether every Chinese label should be considered grammatically a verb; and whether the 500 IDs form a random or otherwise representative sample of the full corpus.

Example prompts that helped

“Extract the required fields, website checks, codebook requirements, and AI declaration from this brief. Do not infer requirements that are not stated.”
“Audit the 500 CSV records against the public NV Atlas ID set. Report exact and normalized matches separately, and never rewrite the source text.”

One thing AI got wrong

My first category map looked plausible but omitted 13 observed lemmas and contained several terms that were not in the data. The build validation caught the mismatch instead of silently assigning those records to a catch-all category. I corrected the map and added an explicit failure condition.

Known limitations

  • The supplied sample is not reproducible from a documented sampling seed, so category percentages describe only this subset.
  • The data includes 12 repeated source sentences; the website counts records separately.
  • Every occurrence of a lemma receives the same category, even where the context suggests an exception.
  • The Chinese_Verb label is analytical shorthand, not a verified grammatical classification.
  • No inter-coder agreement score has yet been calculated.

Reproduce the site

Run python3 scripts/build_corpus.py to rebuild the normalized dataset, then python3 scripts/audit_corpus.py to refresh the public-source reconciliation. Serve the folder over HTTP to run the site locally; GitHub Pages serves the same static files online.

AI 使用聲明

工具及模型

使用 OpenAI Codex 桌面代理，模型版本見 Codex 工作階段。另使用本地 PDF 抽取及靜態網站工具；並查閱公開 NV Atlas 頁面以了解來源及核對記錄。

AI 做了甚麼

  • 閱讀及總結專題要求。
  • 檢查 CSV 的欄位、重複項、編號及詞元數量。
  • 抽取公開 NV Atlas 記錄作核對，沒有生成替代句子。
  • 擬定分類手冊結構、正規化資料欄位，並建立 HTML／CSS／JavaScript 探索器。
  • 起草英文及繁體中文說明文字。
  • 測試網站計算、連結、網址狀態及響應式版面。

我必須親自完成的事

  • 閱讀並批准 50 筆人工核對樣本。
  • 在提交前以自己的文字重寫分類手冊定義。
  • 核實分析，並準備在口頭報告解釋每個類別。
  • 確認公開展示短字幕摘錄符合課程及來源適用條款。

已核實及未核實

已核實：500 個不重複編號、195 個不重複詞元、282 個中文譯法、所有編號均見於公開記錄、481 對正規化後相符。未核實：每個譯法是否好的翻譯；每個中文標籤在語法上是否皆為動詞；以及 500 個編號是否構成整個語料庫的隨機或代表性樣本。

有效的提示例子

「從這份要求中抽取必要欄位、網站檢查、分類手冊要求及 AI 聲明。不要推斷沒有寫明的條件。」
「把 500 筆 CSV 記錄與公開 NV Atlas 編號核對。分開報告完全相符及正規化後相符，永遠不要改寫來源文本。」

AI 曾出錯的地方

我的第一版分類映射看似合理，卻遺漏 13 個實際詞元，並加入幾個資料中不存在的詞。建立資料時的驗證發現不一致，沒有把它們靜默歸入預設類別。我更正映射，並加入明確的失敗條件。

已知限制

  • 提供的樣本不能以已記錄的抽樣種子重現，因此類別百分比只描述這個子集。
  • 資料有 12 個重複原句；網站按記錄逐筆計算。
  • 同一詞元的所有出現均獲同一類別，即使個別語境顯示例外。
  • Chinese_Verb 是分析用簡稱，不是已核實的語法分類。
  • 尚未計算編碼員間一致性。

重現網站

執行 python3 scripts/build_corpus.py 可重建正規化資料；再執行 python3 scripts/audit_corpus.py 更新公開來源核對。以 HTTP 伺服器提供資料夾即可本地瀏覽；GitHub Pages 會提供同一組靜態檔案。
